# 开发日志 · v0.1.2 Installer Finalization + Portable Runtime（2026-09-04）

本日志记录 Agent Risk Guard 从 v0.1.0 到 v0.1.2 的产品化开发轮次，重点是 v0.1.2（Phase A 安装器收尾 + Phase B portable runtime 分发架构）。按时间与阶段如实记录做法、验证与结果。

## 背景与版本演进

仓库最初是「安全规则工程」，通过多轮逐步产品化：

- v1.0.0（历史 tag，2026-08-26）：早期里程碑，保留为发布标记、非稳定版声明。
- v0.1.0 Developer Preview：统一版本语义；建立用户级 CLI（detect / install / status / doctor / uninstall）；非破坏性安装（备份 → merge → manifest）；compatibility.json 单一事实源（D0–D4）。真实 D3 复核：Claude Code 在 bypassPermissions 下被 hook 以 permission-rule 硬阻断、OpenCode 被 `BLOCKED_BY_GLOBAL_SAFETY_GUARD` 拦截。
- v0.1.1 Release Hardening：真事务 install/rollback（transaction.ts：existedBefore / 精确 backup / created-file trash 移除 / rollback 自验证，禁止扫描历史备份）；backup 失败即 ABORT；install 后 runtime self-test（provisional → VERIFY → finalize → COMMIT）；统一 runtime-probe（status / doctor / install-verification 共用）；ACTIVE = 完整 runtime self-test 通过，hook target 缺失 / artifact hash 被改 / node 不可用 → BROKEN；manifest schemaVersion 2 + 原子写；故障注入测试 8 cases；D0–D4 定义统一 + scripts/check-compatibility-docs.ts 防漂移；版本单一源 packages/core/src/version.ts。
- v0.1.2（本轮）：Phase A 安装器最终收尾后冻结核心；Phase B 建立 portable runtime 与 release artifact 分发基础。

## Phase A：安装器收尾（v0.1.2 前半）

发现并修复一个边角事务问题：manifest 之前是事务外的「特殊对象」——install 写 provisional manifest 覆盖旧 manifest 后若 verification 失败，rollback 无条件删除 manifest 文件，导致 repair-install 失败时旧 manifest 没有被恢复（config/hook 恢复了，但系统未完全回到安装前）。

做法：把 manifest 与 config / artifact 统一为 TransactionTarget。`transaction.ts` 的 `writeJsonAtomic` 写前自动 snapshot：旧 manifest 存在则 backup exact + 记录 beforeSha256；不存在则 existedBefore=false、写入后标记 createdByTransaction。删除 noteProvisionalManifest 特殊处理，rollback 走统一规则（restore 精确备份并 sha256 自验证 / trash 移除新建文件）。snapshot 幂等（同路径不重复备份）。

同时让 install 区分 fresh / repair / already：manifest 存在但 wiring 损坏（BROKEN / INSTALLED）时 install 识别为 repair，成功后报 `repaired successfully`；只有「无改动 + 健康 ACTIVE」才报 `already installed`。InstallOutcome 增加 `repaired` 状态。dry-run 也按此显示意图。

## Phase A 验证

- transaction 故障注入测试从 8 增至 10：Case9 覆盖 repair-install 失败恢复旧 manifest（注入 verification 失败后 manifest hash == A、config hash == repair 前、Runtime state 恢复 BROKEN）；Case10 覆盖 repair 成功（删 hook → BROKEN → reinstall → ACTIVE + self-test PASS）。
- 真机验证：人为删 Claude hook → status BROKEN → `riskguard install --agent claude` 输出 `Claude Code: repaired successfully (was BROKEN/INSTALLED); runtime self-test PASS` → status ACTIVE。
- 增加 verificationMode（dynamic / static / none）到 RuntimeProbeResult：Claude Code / Codex 真 spawn hook 做 interception runtime self-test → dynamic；OpenCode / DSH 验证 wiring / artifact / integrity → static。status 与 doctor 如实展示（`Verification: dynamic (real interception runtime self-test)`、`runtime verification: static`），不再把不同强度的验证写成同一含义。
- package.json description 去掉版本号（改稳定描述，升版不再需要同步改）。

## Phase B：Portable runtime 与分发架构（v0.1.2 后半）

目标：用户不必理解 monorepo / packages / TypeScript 源码路径；安装后的 hook 不再依赖 git clone 位置。本轮只搭本地分发基础，不做远程 curl 安装、不做 npm 发布。

新增 `packages/cli/src/runtime-install.ts`（`riskguard bootstrap`）：把最小运行文件集（cli / core / installer / trash / adapters-claude 的 src + assets/opencode/agent-risk-guard.ts + package.json + compatibility.json）复制到 `~/.riskguard/runtime/<version>/`，镜像仓库相对布局；生成 `runtime-manifest.json`（逐文件 path + sha256）。`resolveActiveRoot()`：runtime 已装且完整时，install 的 hook / plugin 指向 runtime 而非 git checkout。

统一 launcher `bin/riskguard.mjs`（仓库内与 artifact 内同构），package.json 加 `bin.riskguard` 与 scripts（riskguard / bootstrap / build-release）。`scripts/build-release.ts` 产出 `dist/agent-risk-guard-v<version>/`（runtime 集 + launcher + runtime-manifest.json + SHA256SUMS.txt）+ tar.gz。
