## 中文

### 这一版要解决什么问题

v0.3.0 证明了"真实会话里能拦住"。这一版要解决的是**另一半**，而且更麻烦：

**「保护看起来在，其实不在」**。下面每一条都是在本机真实复现出来的，不是假设：

1. **脚本在位、哈希正确、套件全绿，入口却没注册。** Claude Code 的 `~/.claude/settings.json` 里
   `PreToolUse` 曾经**丢失**，只剩 `Setup` —— hook 文件是最新版、SHA256 正确、套件全绿，
   但没有任何东西会被触发。**静默裸奔**。
2. **hook 崩溃被当成"非阻断错误"，于是放行。** 相对导入写错时 hook 进程直接崩溃，
   而 Agent 把"hook 崩了"理解为"没问题，继续执行"。
3. **sh 端是 fail-open 的。** 空 stdin / 畸形 JSON / 缺 `command` / 命令含 TAB →
   静默放行，或输出**非法 JSON**（调用方拿不到决策，等价放行）。
4. **密钥明文泄漏。** ps1 hook 把凭据写进日志和 deny 回显；而三端脱敏能力不一致
   （core 9 类 / ps1 10 类 / sh **2 类**）——**sh 的生产出口根本没有接线，而 parity 闸门恒绿**，
   给出的是虚假保证。
5. **两端对同一条命令给出相反判定。** ps1 与 sh 在 20 条语料里有 5 条发散（4 条 sh 漏拦、1 条 sh 误拦）。
6. **"闸门全绿"不等于判据有效。** 有的闸门只测测试入口、从不测生产出口，于是恒绿。

**最值得记住的一条**：修这些问题时，**修复动作本身五次引入了新的放松** ——
一次修复带出 3 个新缺陷（含一个 fail-open）；一次锚化时丢失 **12 处真实拦截**；
一次留下的"包装词选项"放松让 `sudo -u root diskpart` 这类**真实危险命令两端放行**。
所以这一版不只是修 bug，还把「**闸门必须能被证明有效**」变成了常设要求：
每个闸门都要有一个变异体，回退该修复必须让它变红。

### 改变了什么

**让判定可信**
- **CLI 退出码契约**：`0`=成功 / `1`=操作失败 / `2`=用法错误；**hook 运行时恒 `0`**（拒绝是决策，不是错误）。
  同时修复 hook 运行时入口的 fail-open（`tool_input.command` 的形状处理）。
- **doctor 从"查存在"升级为"查新鲜度"**：比对规则条数与 hook 脚本 SHA256 是否与单源一致，不一致报 WARN。
- **ps1 规则 16d 死代码**：`[[:space:]]` 在 .NET 正则里无效 → 该规则**从未生效过**，已修正为 `\s`。

**让失败不再静默**
- **sh hook 改为 fail-closed**：空 stdin / 畸形 JSON / 缺 `command` / 含 TAB / 首行危险+次行 `#`
  → 一律 **deny 且输出合法 JSON**（50 例矩阵：非法 JSON 7→0、裸 exit 2→0、两端分歧 18→2）。
- **ps1 脱敏**：日志与 deny 回显两条出口同时覆盖；随后做**三端脱敏对齐**（走了 REJECT→FIX→FIX2→FIX3
  四轮，根因正是"sh 生产出口从未接线"）。

**让两端说同一种话**
- **跨端判定收敛 + 常设 `decision-parity` 闸门**：语料最终为 **245 条 decision + 24 条跨端身份断言**；
  任何"两端逐条必须同判"的破坏都会在提交前变红。
- **G24**：ps1 rule 16 的 help/version 豁免由**整条命令级抑制**改为**只豁免它自己那次调用**
  （此前 `rm --help; rm <文件>` 会被整条放行）。
- **G3-FIX8**：把包装词**自身的选项**纳入命令位前缀，使 `sudo -u root diskpart`、`nice -n 5 diskpart`
  等 **8 条真实危险命令由两端放行改为两端 deny**（对冻结基线做全量决策差：`deny→allow = 0`）。

**让闸门真的被执行**
- **CI 补全**：sh hook 套件进 macOS + Ubuntu；**ps1 五套 × 双引擎（PowerShell 5.1 与 pwsh 7）
  与 `sh-failclosed-test.sh` 一并进 CI**（此前 ps1 五套**完全不在 CI**）。
- **`test-all.ps1` 对齐**：套件源从**仓库外**改到仓库内、补齐两个**从未在本地跑过**的跨端 parity 闸门、
  并修掉它自身"UTF-8 无 BOM 导致 PowerShell 5.1 根本解析不了"的缺陷。
- **接线自愈不再写回失效注册**：`-Fix` 模板的带引号 `-File "<路径>"` 实测会让 hook 静默失效，
  改为路径无空白时不加引号。

**顺带**：回收站清空类绕过拦截、macOS/Linux 跨平台规则缺口修复、DSH 块设备规则修订。

### 验证

- **8 个切片逐个独立验收**（G1+G7 / G2 / G4 / G5 / G15 / G15b / G24 / G3-FIX8），
  其中 **G15b 与 G3-FIX8 各经历 REJECT → Repair → PASS 多轮**，每次裁决都留下可复现证据。
- 闸门状态：`decision-parity` 245 + 24 全绿；**变异体验证非自证**（回退修复 → 恰好新增语料变红）；
  ps1 五套 × 3 棵树 × 双引擎 **28/28**；sh 四套 × 3 棵树 **12/12**；node 全仓 **380/380**。
- 分发面：**ps1 ×7 + sh ×3 同哈希**，ps1 **BOM 逐份为 True**（此前有一份漏带 BOM 的旧副本仍在分发，
  且其中仍含已修的漏洞）。
- 本机接线：Claude Code / Codex / AGY 的 `PreToolUse` 真实拦截复核；只读接线巡检 exit 0、无 `[!!]`。

## English

### The problem this release solves

v0.3.0 proved "it blocks in a real session". This release tackles **the other half**, and the harder one:

**"It looks protected, but it is not."** Every item below was reproduced on a real machine, not assumed:

1. **The script was present, the hash was right, the suites were green — and the entry point was not
   registered.** Claude Code's `~/.claude/settings.json` had **lost** its `PreToolUse` entry, leaving only
   `Setup`: the hook file was current, its SHA256 matched, every suite passed, and nothing would ever trigger.
   **Silent, unprotected.**
2. **A crashing hook was treated as a non-blocking error — so the command went through.** A wrong relative import
   made the hook process die, and the agent read "the hook crashed" as "fine, continue".
3. **The sh side failed open.** Empty stdin / malformed JSON / a missing `command` / a command containing a TAB
   led to a silent allow, or to **invalid JSON** (the caller gets no decision, which is equivalent to allowing).
4. **Secrets leaked in cleartext.** The ps1 hook wrote credentials into its log and into the deny echo, and the
   three ends had unequal redaction coverage (core 9 classes / ps1 10 / sh **2**) — **the sh production exit was
   never wired, while the parity gate stayed green**, giving a false guarantee.
5. **The two ends disagreed about the same command.** ps1 and sh diverged on 5 of 20 payloads (4 sh misses,
   1 sh false positive).
6. **"All gates green" did not mean the criteria were sound.** Some gates only exercised test entry points and
   never the production exit, so they were green by construction.

**The lesson worth keeping**: while fixing these, **the fixes themselves introduced five new relaxations** — one
repair brought 3 new defects (including a fail-open); one anchoring pass **dropped 12 genuine interceptions**;
one leftover "wrapper options" relaxation let real dangerous commands such as `sudo -u root diskpart` through on
**both** ends. So this release does not only fix bugs: it makes "**a gate must be provably effective**" a standing
requirement — every gate needs a mutant, and reverting the fix must turn it red.

### What changed

**Making decisions trustworthy**
- **CLI exit-code contract**: `0` = success / `1` = operation failed / `2` = usage error; **the hook runtime always
  exits `0`** (a denial is a decision, not an error). The hook runtime entry's fail-open handling of the
  `tool_input.command` shape was fixed alongside it.
- **`doctor` went from "is it present?" to "is it current?"**: it compares the rule count and the hook script's
  SHA256 against the single source and warns on mismatch.
- **ps1 rule 16d was dead code**: `[[:space:]]` is invalid in a .NET regex, so the rule **had never worked**;
  corrected to `\s`.

**Making failure non-silent**
- **The sh hook is now fail-closed**: empty stdin / malformed JSON / missing `command` / a TAB / a dangerous first
  line followed by a `#` comment line → **always deny, always valid JSON** (50-case matrix: invalid JSON 7→0,
  bare exit 2→0, cross-end divergence 18→2).
- **ps1 redaction** now covers both exits (log and deny echo), followed by a **three-end redaction alignment**
  that took four rounds (REJECT→FIX→FIX2→FIX3) — the root cause being exactly that the sh production exit had
  never been wired.

**Making both ends speak the same language**
- **Cross-end decision convergence plus a standing `decision-parity` gate**: the corpus ended at **245 decision
  cases + 24 cross-end identity assertions**, so any break of "both ends must decide identically" goes red before
  a commit.
- **G24**: rule 16's help/version exemption changed from **suppressing the whole command** to **exempting only the
  invocation that is itself a help call** (previously `rm --help; rm <file>` was allowed wholesale).
- **G3-FIX8**: a wrapper command's **own options** are now part of the command-position prefix, so **8 real
  dangerous commands** (`sudo -u root diskpart`, `nice -n 5 diskpart`, …) went from allowed on both ends to
  **denied on both ends** (full decision diff against the frozen baseline: `deny→allow = 0`).

**Making the gates actually run**
- **CI coverage**: the sh hook suites now run on macOS + Ubuntu, and **the five ps1 suites (under both Windows
  PowerShell 5.1 and pwsh 7) plus `sh-failclosed-test.sh` run in CI** — the ps1 suites had previously been
  **entirely absent from CI**.
- **`test-all.ps1` aligned**: its suite source moved from **outside the repo** to inside it, the two cross-end
  parity gates that had **never run locally** were added, and its own defect — UTF-8 without a BOM, which Windows
  PowerShell 5.1 could not even parse — was fixed.
- **The wiring self-heal no longer writes a dead registration**: its quoted `-File "<path>"` form was measured to
  silently disable the hook; it now omits the quotes when the path has no spaces.

**Also**: recycle-bin-emptying bypasses are blocked, macOS/Linux cross-platform rule gaps were closed, and the DSH
block-device rule was revised.

### Verification

- **Eight slices independently evaluated** (G1+G7 / G2 / G4 / G5 / G15 / G15b / G24 / G3-FIX8), with **G15b and
  G3-FIX8 each going through REJECT → repair → PASS** over several rounds, and reproducible evidence for every
  verdict.
- Gate status: `decision-parity` 245 + 24 green, with **mutants proving it is not self-fulfilling** (reverting a
  fix turns exactly the new corpus red); the five ps1 suites across 3 trees × 2 engines **28/28**; the four sh
  suites across 3 trees **12/12**; the full node suite **380/380**.
- Distribution surface: **ps1 ×7 and sh ×3 byte-identical within each role**, with **BOM=True on every ps1**
  (one stale copy lacking a BOM was still being distributed, and it still contained the fixed hole).
- On a real machine: `PreToolUse` interception re-verified for Claude Code / Codex / AGY; the read-only wiring
  inspection exits 0 with no `[!!]`.
