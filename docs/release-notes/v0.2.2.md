## 中文

### 这一版要解决什么问题

两个洞，都不显眼但都真：

1. **协议错误会被当成安全结论。** 一个 schema 合法、但 `acs_version` 是我们不支持的请求，会被**当成 0.1.0
   继续处理**。调用方以为"协议通了"，其实我们只是没看懂它说的是哪一版规范。更糟的是，这种"协议层错误"
   和"策略层拒绝"混在一起时，外面看到的 `deny` 到底是因为**危险**还是因为**没读懂**，分不清楚。
2. **发版不等于可下载。** GitHub Release 上只有 Source code，没有可校验的制品 —— 也就是没有一个
   "这个文件确实是这次发布产出的"的证据。发布不可复现。

### 改变了什么

- **ACS 版本门禁**：`SUPPORTED_ACS_SPEC_VERSIONS = ['0.1.0']`，**精确 pin** —— 不接受 `0.1.x` / `0.x` /
  `latest` / semver range / 协商。
- **错误语义三分**：不支持的版本 → ACS application error `-32001`；schema 非法 → `-32602`；
  危险操作 → policy DENY。三者**严格区分**，未知版本绝不 fallback 到 0.1.0 逻辑，也绝不出现在 Policy Engine 里。
- **`release.yml` 真正的发布门禁**：tag `v*` 触发 → 双 Node（22/24）全量验证（测试 + schema conformance +
  制品 hash）全 PASS 才 `gh release create`，上传 `agent-risk-guard-v*.tar.gz` + 根目录 `SHA256SUMS.txt`（Pre-release）。

### 验证

双 Node 上测试、schema conformance、制品校验和全部通过后才允许上传（任一失败 → 不上传）。
协议层冻结后，核心转向 v0.3.0 Real Agent Conformance。

## English

### The problem this release solves

Two unglamorous but real holes:

1. **A protocol error could be mistaken for a security decision.** A request that was schema-valid but carried an
   `acs_version` we do not support was **handled as if it were 0.1.0**. The caller thought "the protocol worked";
   in reality we had not understood which spec version it was speaking. Worse, with protocol errors and policy
   denials mixed together, an outside observer could not tell whether a `deny` meant **dangerous** or
   **not understood**.
2. **A release was not downloadable.** GitHub Releases shipped only "Source code" — no verifiable artifact, i.e.
   no evidence that a file was actually produced by that release. The release was not reproducible.

### What changed

- **ACS version gate**: `SUPPORTED_ACS_SPEC_VERSIONS = ['0.1.0']`, an **exact pin** — no `0.1.x` / `0.x` /
  `latest` / semver range / negotiation.
- **Error semantics split three ways**: unsupported version → ACS application error `-32001`; schema-invalid →
  `-32602`; dangerous operation → policy DENY. The three are **strictly separated**; an unknown version never
  falls back to 0.1.0 logic and never reaches the policy engine.
- **A real release gate in `release.yml`**: a `v*` tag triggers dual-Node (22/24) verification (tests + schema
  conformance + artifact hashes); only if everything passes does `gh release create` upload
  `agent-risk-guard-v*.tar.gz` plus a root `SHA256SUMS.txt` (pre-release).

### Verification

Tests, schema conformance and artifact checksums must all pass on both Node versions before anything is
uploaded (any failure → no upload). With the protocol layer frozen, the core moved on to v0.3.0 Real Agent
Conformance.
