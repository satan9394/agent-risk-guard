## 中文

### 这一版要解决什么问题

v0.2.0 让 RiskGuard 会说 ACS，但只要求它通过**我们自己写的简化校验**。于是它可以说"已对齐 OWASP ACS"，
却**过不了官方 JSON Schema** —— 这恰恰是这个项目最想消灭的那类东西：**看起来合规**。
对一个安全边界协议来说，"像"和"是"之间的差距，就是集成方误判风险的差距。

### 改变了什么

- **官方 schema 快照 pinned**：`tests/vendor/owasp-acs-v0.1.0/`（upstream commit `f46d260`，
  GenAI-Security-Project/agent-control-standard，Apache-2.0）。
- **官方 JSON Schema 成为最终判据**（ajv Draft 2020-12 + ajv-formats），自此是 **Release Gate**；
  本地 validator 降为 Layer 1（快、友好、fail-closed）。
- **JSON-RPC 信封与 wire 模式**：`acs evaluate --wire` 走官方 Request/Response Envelope；
  `response.id` 回显 `request.id`、`result.request_id` 回显 `params.request_id`。
- **错误语义分离**：`-32700`（非法 JSON）/ `-32600`（非法信封）/ `-32602`（非法参数）与
  **policy deny + `degraded=true`**（安全映射失败）严格区分，不把协议错误伪装成拒绝结果。
- **capability 推导**：官方 capability 可选，缺失时从 tool/operation/raw_command 推导；
  **推导不确定 → fail-closed deny**（绝不静默重新解释）。
- **官方结构对齐**：`modifications` 改为官方结构；**无法安全表达改写时直接 deny**（不伪造 modify）；
  `ask_details` / `defer_details` 对齐官方 schema。
- **schema 完整性**：`SCHEMA_SHA256SUMS` + `scripts/verify-acs-schema-snapshot.ts`（CI 校验）——
  防"为了让测试通过而改官方 schema"。

### 验证

全量 **277/277 通过**（含 31 项官方 schema conformance + 快照完整性）。
定位：**Experimental OWASP ACS v0.1.0 schema-conformant wire gateway** —— 不是 compliant，也不是 certified。

## English

### The problem this release solves

v0.2.0 taught RiskGuard to speak ACS, but only required it to pass **our own simplified validation**. So it could
claim "aligned with OWASP ACS" while **failing the official JSON Schema** — precisely the thing this project
exists to eliminate: **looking compliant**. For a security boundary protocol, the gap between "looks like" and
"is" is the gap through which an integrator misjudges risk.

### What changed

- **Official schema snapshot pinned**: `tests/vendor/owasp-acs-v0.1.0/` (upstream commit `f46d260`,
  GenAI-Security-Project/agent-control-standard, Apache-2.0).
- **The official JSON Schema is now the final judge** (ajv Draft 2020-12 + ajv-formats) and a **Release Gate**;
  the local validator is demoted to Layer 1 (fast, friendly, fail-closed).
- **JSON-RPC envelopes and wire mode**: `acs evaluate --wire` speaks the official Request/Response envelopes;
  `response.id` echoes `request.id` and `result.request_id` echoes `params.request_id`.
- **Error semantics separated**: `-32700` (invalid JSON) / `-32600` (invalid envelope) / `-32602` (invalid params)
  are strictly distinguished from **policy deny + `degraded=true`** (safety mapping failed) — a protocol error is
  never disguised as a denial.
- **Capability derivation**: the official `capability` is optional and is derived from
  tool/operation/raw_command when absent; **uncertain derivation → fail-closed deny** (never a silent
  reinterpretation).
- **Official structures**: `modifications` now uses the official shape, and **when a safe rewrite cannot be
  expressed we deny instead of fabricating a modify**; `ask_details` / `defer_details` match the official schema.
- **Schema integrity**: `SCHEMA_SHA256SUMS` + `scripts/verify-acs-schema-snapshot.ts` (checked in CI) — so nobody
  can edit the vendor schema to make tests pass.

### Verification

**277/277 tests pass** (including 31 official schema conformance cases plus snapshot integrity).
Positioning: an **Experimental OWASP ACS v0.1.0 schema-conformant wire gateway** — not compliant, not certified.
