## 中文

### 这一版要解决什么问题

在此之前，RiskGuard 只是一堆规则和脚本。它没有"可安装、可验证、可卸载"的形态，而且**发布前的 Release Gate
查出了两个真实的 fail-open** —— 也就是说，装了也可能等于没装：

1. **hook 一执行就崩**：`pre-tool-hook.ts` 的相对导入在安装路径下解析到不存在的目录，hook 进程
   `ERR_MODULE_NOT_FOUND` 崩溃；而 **Claude Code 把 hook 崩溃视为"非阻断错误"，于是命令照常放行**。
   保护脚本在，看着像装好了，实际一条都没拦。
2. **DENY 输出格式不合法**：hook 输出的 JSON 缺少 `hookEventName`，Claude Code 判为不合法 JSON，
   同样按非阻断错误放行 —— **我们拒绝了，但对方没收到**。

同类问题还有：`status` 会因为"配置里有一串字符"就报 ACTIVE；损坏/无权限的配置可能被覆盖；
同名但不是我们的插件文件可能被覆盖。

### 改变了什么

- **用户级 CLI**：`detect` / `install` / `status` / `doctor` / `uninstall`（零依赖、零构建，Node ≥ 22.18）。
- **非破坏性安装**：写前备份、配置 **merge 而非 replace**、安装 manifest、幂等安装/卸载、`--dry-run`、`--verbose`。
- **发布前整改（v0.1.0 Release Gate）**：
  - `status` 拆成 **Capability（D0–D4）** 与 **Runtime state（NOT_DETECTED / DETECTED / INSTALLED / ACTIVE / BROKEN）**
    —— 检测到 Agent 且能力非 D0 不再等于 ACTIVE；
  - **类型化配置读取**：损坏 / 无权限 / IO 错误的配置 → install 立即终止且**零写入**，绝不覆盖无法确认内容的用户配置；
  - **插件命名空间**：OpenCode 插件改为 `agent-risk-guard.ts`；目标同名但内容不是我们的（SHA256 不符）→ **拒绝安装、零覆盖**；
  - **事务式安装**：preflight → backup → write → manifest → doctor，任一步失败回滚到安装前，不留半成品；
  - manifest 增加 `schemaVersion` 与 `artifacts[{path, sha256}]`；卸载前校验哈希，**被用户改过的文件不自动删除**；
  - 卸载是**精确逆操作**（当前配置 − 我们注入的条目），保留用户之后新增的配置。
- **修掉上面两个 fail-open**（补 `hookEventName`、修正相对导入），并在真实会话中验证能以 `permission-rule` 硬阻断。
- **真实 D3 实测**：Claude Code（`--permission-mode bypassPermissions`）与 OpenCode 会话中 `git reset --hard`
  在工具执行前被拒，未提交改动存活。
- **兼容性单一事实源** `packages/installer/compatibility.json`；README 支持矩阵以它为准。
- 新增 `tests/release-hardening/`：17 项单测 + 7 项完整生命周期 E2E（全新 HOME → detect → install → ACTIVE →
  doctor PASS → 二次安装幂等 → 用户新增配置 → uninstall → 全部保留；非法 JSON 拒装零写入；同名异内容插件拒装；
  人为删 hook → BROKEN）。

### 验证

本地全量 **177 passed / 0 failed**；CI（Node 22/24，Ubuntu）green（171 pass，6 项 Windows-only 按设计 skip）。

## English

### The problem this release solves

Until this version RiskGuard was a pile of rules and scripts. It had no installable / verifiable / uninstallable
form — and the pre-release gate found **two real fail-opens**, i.e. you could install it and still be unprotected:

1. **The hook crashed on every run**: a relative import in `pre-tool-hook.ts` resolved to a non-existent
   directory under the install path, so the hook process died with `ERR_MODULE_NOT_FOUND` — and **Claude Code
   treats a crashing hook as a non-blocking error and let the command through**. The protection script was
   present, it looked installed, and it blocked nothing.
2. **The DENY output was malformed**: the hook's JSON was missing `hookEventName`, Claude Code judged it invalid
   JSON and again treated it as a non-blocking error — **we denied, and the other side never heard it**.

Related issues: `status` reported ACTIVE because "a string exists in the config"; a corrupt or
permission-denied config could be overwritten; a same-named file that was not ours could be clobbered.

### What changed

- **A user-level CLI**: `detect` / `install` / `status` / `doctor` / `uninstall` (zero dependencies, zero build,
  Node ≥ 22.18).
- **Non-destructive install**: back up before writing, **merge rather than replace** config, an install manifest,
  idempotent install/uninstall, `--dry-run`, `--verbose`.
- **Pre-release hardening (the v0.1.0 release gate)**:
  - `status` split into **Capability (D0–D4)** and **Runtime state (NOT_DETECTED / DETECTED / INSTALLED / ACTIVE /
    BROKEN)** — detecting an agent with a non-D0 capability no longer means ACTIVE;
  - **typed config reads**: a corrupt / permission-denied / IO-error config aborts the install with **zero
    writes**; a user config whose contents cannot be confirmed is never overwritten;
  - **plugin namespace**: the OpenCode plugin is deployed as `agent-risk-guard.ts`; a same-named target that is
    not ours (SHA256 mismatch) is **refused with zero overwrite**;
  - **transactional install**: preflight → backup → write → manifest → doctor, rolling back on any failure and
    leaving no half-installed state;
  - the manifest gained `schemaVersion` and `artifacts[{path, sha256}]`; uninstall verifies hashes and **does not
    delete files the user has modified**;
  - uninstall is the **exact inverse** (current config minus our injected entries) and preserves config the user
    added afterwards.
- **Both fail-opens fixed** (adding `hookEventName`, correcting the relative import) and verified in real
  sessions where the hook now hard-blocks via `permission-rule`.
- **Real D3 testing**: in Claude Code (`--permission-mode bypassPermissions`) and OpenCode sessions,
  `git reset --hard` was refused before the tool ran and uncommitted changes survived.
- **A single source of truth for compatibility** at `packages/installer/compatibility.json`; the README support
  matrix follows it.
- New `tests/release-hardening/`: 17 unit tests plus 7 full-lifecycle E2E cases (fresh HOME → detect → install →
  ACTIVE → doctor PASS → idempotent re-install → user adds config → uninstall → everything preserved; invalid
  JSON refused with zero writes; same-name different-content plugin refused; manually deleted hook → BROKEN).

### Verification

**177 passed / 0 failed** locally; CI (Node 22/24, Ubuntu) green (171 pass; the 6 Windows-only tests skip by
design).

> Note: the historical Git tag `v1.0.0` (2026-08-26) is kept as a release marker and is **not** a current
> stability claim.
