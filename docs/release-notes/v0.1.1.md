## 中文

### 这一版要解决什么问题

v0.1.0 能装了，但"装成功"**不等于"真的在工作"**。这一版把安装 / 回滚 / 健康检查 / 状态判定做成真正的闭环，
消灭三类**表面成功**：

- **安装"成功"但留下残留**：备份失败还继续写、回滚去扫描历史 backup 目录（可能恢复到不属于本次的旧文件）、
  回滚没验证就报成功。
- **状态"ACTIVE"但没有依据**：只看配置里有没有一段字符串，而不是**真的执行一次**拦截自检。
- **等级定义散落**：D0–D4 在多个文档里各写一套，读到哪份算哪份。

### 改变了什么

- **真事务安装**（`InstallTransaction`）：`PRECHECK → SNAPSHOT/BACKUP → WRITE → VERIFY → COMMIT`，
  每个目标记录 `{path, existedBefore, backupPath, createdByTransaction}`。
- **备份失败即 ABORT**：任一"已存在"目标备份失败 → 立即终止且**零写入**（禁止 best-effort）。
- **回滚只用本轮事务的精确备份**：**禁止扫描历史 backup 目录**；原文件不存在 → 用 trash 移除本轮创建的文件；
  原文件存在 → restore 精确备份；回滚后自校验（sha256 / 目标不存在），不满足报 `ROLLBACK_INCOMPLETE`，**绝不谎报成功**。
- **安装后 runtime 自检**：真实 spawn hook，无害 payload → ALLOW、危险 payload → DENY；**PASS 才 finalize manifest + COMMIT**，
  FAIL 自动回滚。
- **统一 runtime probe**：status / doctor / install-verification 共用同一判定；**ACTIVE 仅在完整自检通过时报告**；
  hook 目标缺失 / 插件制品哈希被改 / node 不可用 → **BROKEN**。
- **Manifest schemaVersion 2**：`transactionId` / `artifacts[].createdByInstall` / `runtimeVerification`；
  manifest 与配置均**原子写**（write temp → rename）。
- **故障注入测试** `tests/transaction/`（8 例）：manifest 写失败、created-file 校验失败、备份失败、配置写失败、
  制品失败、hook 目标丢失、制品哈希改变、runtime 不可用。
- **D0–D4 单一事实源**：权威定义只在 `packages/installer/compatibility.json`；
  `scripts/check-compatibility-docs.ts`（CI 跑）扫描 README / docs / CHANGELOG 防旧定义漂移。
- **版本单一源**：`packages/core/src/version.ts` 从 `package.json` 读，CLI 与 manifest 不再各自硬编码。

### 验证

本地全量 **185 passed / 0 failed**；CI green（179 pass，6 项 Windows-only 按设计 skip）。
真机 4 个 Agent（Claude Code / OpenCode / Codex / DSH）：install → ACTIVE（自检 PASS）→ uninstall **零残留**。

## English

### The problem this release solves

v0.1.0 could install, but **"installed successfully" did not mean "actually working"**. This release turns
install / rollback / health-check / state into a real closed loop and removes three kinds of **apparent success**:

- **"Installed" but leaving residue**: a failed backup did not stop the write; rollback scanned historical backup
  directories (and could restore a file that did not belong to this run); rollback reported success without
  verifying.
- **"ACTIVE" with nothing behind it**: it only checked whether a string appeared in the config, instead of
  **actually running** an interception self-test.
- **Level definitions scattered**: D0–D4 were written differently in several documents, so whichever one you
  read became your truth.

### What changed

- **A real transactional install** (`InstallTransaction`): `PRECHECK → SNAPSHOT/BACKUP → WRITE → VERIFY → COMMIT`,
  recording `{path, existedBefore, backupPath, createdByTransaction}` for every target.
- **A failed backup aborts**: if backing up any pre-existing target fails, the install stops immediately with
  **zero writes** (no best-effort).
- **Rollback uses only this run's exact backups**: scanning historical backup directories is **forbidden**; if the
  original file did not exist, the file this run created is removed with trash; if it did exist, the exact backup
  is restored; rollback re-verifies itself (sha256 / target absent) and reports `ROLLBACK_INCOMPLETE` rather than
  **ever claiming a false success**.
- **Post-install runtime self-test**: a real hook spawn where a harmless payload must ALLOW and a dangerous one
  must DENY; only on PASS is the manifest finalised and the transaction committed — on FAIL it rolls back
  automatically.
- **A unified runtime probe**: status / doctor / install-verification share one judgement; **ACTIVE is reported
  only when the full self-test passes**; a missing hook target, a modified plugin artifact hash, or an
  unavailable node runtime yields **BROKEN**.
- **Manifest schemaVersion 2**: `transactionId` / `artifacts[].createdByInstall` / `runtimeVerification`; both the
  manifest and config are written **atomically** (write temp → rename).
- **Fault-injection tests** in `tests/transaction/` (8 cases): manifest write failure, created-file verify
  failure, backup failure, config write failure, artifact failure, hook target loss, artifact hash change,
  runtime unavailable.
- **A single source of truth for D0–D4**: the authoritative definition lives only in
  `packages/installer/compatibility.json`; `scripts/check-compatibility-docs.ts` (run in CI) scans README / docs /
  CHANGELOG for stale definitions.
- **A single version source**: `packages/core/src/version.ts` reads `package.json`; the CLI and manifest no longer
  hard-code their own.

### Verification

**185 passed / 0 failed** locally; CI green (179 pass; the 6 Windows-only tests skip by design).
On a real machine, four agents (Claude Code / OpenCode / Codex / DSH) went install → ACTIVE (self-test PASS) →
uninstall with **zero residue**.
