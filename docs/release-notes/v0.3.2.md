## 中文

### 这一版要解决什么问题

v0.3.1 让「保护已生效」这句话可自证 —— 但自证的是**我们写下的那些规则**。这一版暴露的是另一半：

**规则本身漏了两种语义等价的写法，而 Agent 完全可以用它们删掉你的分支。**

1. **长选项整条绕过。** 规则只认 `-d` / `-D`。而 `git branch --delete <name>` 与
   `git branch --delete --force <name>` 在 git 里与 `-D` 语义完全相同，却**在所有 enforcement 层一律放行**
   （opencode 插件、installer deny 规则、ps1 hook ×3、sh hook、DSH patch ×2）。
   更糟的是 `isReadOnlyCommand` 把它判成**只读**，于是走 read-only 快路径**直接 allow** —— 连分类都没发生。
2. **修第一版时又漏了合并短选项（本版重点）。** 第一版修复（R7）给短选项分支加了尾部 `\b`，于是 git 的
   **合并短选项** —— `-df` ≡ `-d -f` ≡ `-D`，**真机实测确实删除分支** —— 在 `classifyShellCommand` 与
   `isReadOnlyCommand` 两处都不再命中，由 `RG-GIT-001` DENY 变成 `RG-UNKNOWN-001` allow。
   隔离上下文的独立验收实测 **38 条放宽、其中 24 条可被真实 git 利用**，因此把 R7 裁定为 **REJECT**，退回重做。

**放着不管会怎样**：一个执行 `git branch -Df <name>` 的 Agent，在 CLI 与全部 adapter 链路上都不再被拦截，
而 `-Df` 在 git 里与 `-D` 等价。这不是理论风险 —— 24 条这样的形态由 DENY 变 ALLOW 是可复现、可测量的。

### 改变了什么

- **规则统一为 `(?:-[A-Za-z]*[dD]|--delete\b)`**，覆盖 9 个 enforcement 层（opencode 插件 ×2、ps1 ×3、
  installer deny 规则、DSH patch ×2、sh）。`-[A-Za-z]*[dD]` 同时覆盖单独的 `-d`/`-D` 与合并形式
  `-df`/`-Df`/`-dd`/`-Dd`/`-dfd`，长选项 `--delete` 单独一条。
- **测试锁定语义**：`tests/adversarial/rule-self-test.test.ts` 与 `packages/core/test/normalize.test.ts`
  加入合并短选项正例（`isReadOnlyCommand` + `classifyShellCommand` 双向断言），并保留 `-m a b` / `-c` 的只读断言。
- **更正一处声明与实际不符**：此前称「顺带把 `isReadOnlyCommand` 白名单补全为 `-[dDmMcC]\b|--delete|--move|--copy|--force`」，
  实测**规范形态下并未生效** —— `^git\s+branch\s*` 的 `\s*` 已吞掉 `branch` 与首个选项之间的空格。
  该补全方向安全，但描述已改正，不再声称「此前漏判」。
- **生产面与派生物同步**：DSH `~/.dsh/profiles/{web,headless}` 与 `agent-risk-guard-audit` skill 镜像此前
  落后单源多个版本（缺 G3-FIX8、缺 R7），属「比单源弱」的旁路副本，已全部回灌单源。
- **`riskguard-wiring-check.ps1` 加固**：DSH 校验从「比规则条数」升级为**逐条正则文本比对** + `-Fix`
  （旧实现只比条数，规则被等量替换时静默通过 —— 这正是 R7 的收紧长期没落到 DSH 生产面的原因）；
  新增 `[skill 副本]` 段逐文件比对，镜像按内容等价比对、忽略行尾。
- **`sync-prod.ps1` 重写为薄封装**，委派给 `riskguard-wiring-check.ps1`。原实现每次运行都会把同样 5 条
  R2 规则**重复追加**进 DSH patch（幂等性为零），并把插件写到过时的 `destructive-operation-guard.ts`
  （现网加载 `agent-risk-guard.ts` → 重复插件文件）。

### 验证

- **9 层 × 9 条「必拦」形态 = 0 漏拦、0 误伤**；core 层对真机 git 基准（`probe-git-truth.mjs`）同样 0 漏拦 0 误伤。
- 规则相关套件 **71/71**；`sh-audit-bypass.sh` **195/195**；`sh-hook-test.sh` **70/70**；
  17 个测试目录**逐个单独跑**全部 exit 0。
- **变异体证明闸门非自证式**：把正则该回 R7 初版形态后，`-df`/`-Df`/`-dd`/`-Dd`/`-dfd` 5 条组合全部漏拦。
- **已部署的生产层实跑**：ps1 hook 对 `-df`/`-Df`/`-dd`/`--delete` 全部 DENY，`-m a b` / `-a` 正确放行。
- `riskguard-wiring-check.ps1` **exit 0**（ps1 ×3、opencode 插件、DSH 69 条逐条一致、skill 39 个文件等价）；
  `doctor` **4 PASS / 0 WARN / 0 FAIL**。
- **未验证**：macOS / Linux 的真实回收站行为，以及 Cursor / Windsurf / Copilot CLI 的真实会话拦截 —— 仍待补测，
  见 [`docs/TODO.md`](https://github.com/satan9394/agent-risk-guard/blob/main/docs/TODO.md)。

## English

### The problem this release solves

v0.3.1 made the claim "protection is live" self-proving — but it only proved **the rules we had written**. This
release exposes the other half:

**the rules missed two equivalent spellings, and an agent could use either to delete your branches.**

1. **The long option bypassed everything.** The rule only knew `-d` / `-D`, while `git branch --delete <name>` and
   `git branch --delete --force <name>` mean exactly the same as `-D` in git, yet were **allowed by every
   enforcement layer** (opencode plugin, installer deny rules, ps1 hook ×3, sh hook, DSH patch ×2). Worse,
   `isReadOnlyCommand` classified it as **read-only**, so it took the read-only fast path and was **allowed without
   ever being classified**.
2. **The first fix then missed combined short flags (the focus of this release).** The first fix (R7) added a
   trailing `\b` to the short-option branch, so git's **combined short flags** — `-df` ≡ `-d -f` ≡ `-D`, and real
   git does delete the branch — stopped matching in both `classifyShellCommand` and `isReadOnlyCommand`,
   flipping `RG-GIT-001` DENY to `RG-UNKNOWN-001` allow. An isolated evaluator measured **38 relaxations, 24 of
   them exploitable by real git**, and rejected R7.

**If left unfixed**: an agent running `git branch -Df <name>` is not blocked on the CLI or any adapter path, and
`-Df` is equivalent to `-D` in git. This is not theoretical — 24 such forms moving from DENY to ALLOW is
reproducible and measurable.

### What changed

- **The rule is now `(?:-[A-Za-z]*[dD]|--delete\b)`** across all 9 enforcement layers (opencode plugin ×2, ps1 ×3,
  installer deny rules, DSH patch ×2, sh). `-[A-Za-z]*[dD]` covers both plain `-d`/`-D` and the combined forms
  `-df`/`-Df`/`-dd`/`-Dd`/`-dfd`; the long option `--delete` is a separate branch.
- **Tests pin the semantics**: `tests/adversarial/rule-self-test.test.ts` and
  `packages/core/test/normalize.test.ts` gained combined-short-flag positives
  (`isReadOnlyCommand` + `classifyShellCommand`, both directions) and keep `-m a b` / `-c` read-only.
- **A false claim was corrected**: an earlier note said the `isReadOnlyCommand` allowlist had been completed with
  `--move`/`--copy`/`--force`. Measured, that **never took effect for normal invocations** — `^git\s+branch\s*`
  already swallows the space between `branch` and the first option. The change is direction-safe, but the wording
  no longer claims a fix that did not happen.
- **Production surfaces and derived copies re-synced**: the DSH `~/.dsh/profiles/{web,headless}` profiles and the
  `agent-risk-guard-audit` skill mirror lagged the single source by several releases (missing G3-FIX8 and R7) and
  were weaker than it; all were restored from the single source.
- **`riskguard-wiring-check.ps1` hardened**: the DSH check now compares **every rule regex one by one** instead of
  comparing rule counts, and can `-Fix` from the single source. The old count-only check passed an equal-size swap
  silently — which is exactly why R7's tightening never reached DSH. A `[skill mirror]` section compares the
  installed skill file by file (content-equivalent, line endings ignored).
- **`sync-prod.ps1` rewritten as a thin wrapper** delegating to `riskguard-wiring-check.ps1`. Its old body appended
  the same 5 R2 rules to the DSH patch on every run (zero idempotency) and wrote the opencode plugin to the
  obsolete `destructive-operation-guard.ts`, while production loads `agent-risk-guard.ts`.

### Verification

- **9 layers × 9 must-block forms = 0 misses, 0 false positives**; the core layer matches the real-git baseline
  (`probe-git-truth.mjs`) with 0 misses and 0 false positives.
- Rule suites **71/71**; `sh-audit-bypass.sh` **195/195**; `sh-hook-test.sh` **70/70**; all 17 test directories
  pass when run individually.
- **Mutation proof that the gates are not self-fulfilling**: reverting the rule to its R7 form makes all five
  combinations (`-df`/`-Df`/`-dd`/`-Dd`/`-dfd`) slip through.
- **Deployed layers exercised for real**: the ps1 hook denies `-df`/`-Df`/`-dd`/`--delete` and still allows
  `-m a b` / `-a`.
- `riskguard-wiring-check.ps1` exits **0** (ps1 ×3, opencode plugin, DSH 69 rules matched one by one, skill 39
  files equivalent); `doctor` reports **4 PASS / 0 WARN / 0 FAIL**.
- **Not verified**: real recycle-bin behaviour on macOS / Linux, and real in-session blocking for Cursor /
  Windsurf / Copilot CLI — see [`docs/TODO.md`](https://github.com/satan9394/agent-risk-guard/blob/main/docs/TODO.md).
