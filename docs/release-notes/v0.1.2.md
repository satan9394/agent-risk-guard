## 中文

### 这一版要解决什么问题

三件事，都指向同一个后果 —— **你以为是保护，其实早就断了**：

1. **hook 指向 git clone**。安装时把 Agent 的 hook 指到源码仓库路径，于是**仓库一移动、一改名、一删除，
   保护就静默失效**，而状态页可能还显示正常。
2. **manifest 不在事务快照里**。安装/修复失败回滚时，配置文件回去了，manifest 却没有 —— 留下一个
   "记录与实际不符"的状态，下一次 repair 会据此误判。
3. **所有 ACTIVE 长得一样**。真实 spawn 危险载荷自检通过的（dynamic）和只检查了接线与哈希的（static），
   在状态输出里**被写成一视同仁**，用户无法区分"验证过"和"看起来配好了"。

### 改变了什么

- **manifest 纳入 transaction snapshot**：旧 manifest 安装前 backup exact（回滚时 restore 并 sha256 校验），
  不存在则 `existedBefore=false`（回滚移除新建）。
- **repair 识别**：manifest 存在但接线损坏（BROKEN / INSTALLED）→ install 走 repair 语义并报
  `repaired successfully`，不再误报 `already installed`；只有"无改动 + 健康 ACTIVE"才算已安装。
- **`verificationMode` 如实展示**：`dynamic`（Claude Code / Codex：真实执行 interception 自检）/
  `static`（OpenCode / DSH：接线 + 制品 + 完整性）/ `none`；status 与 doctor 都显示，不再一视同仁。
- **可移植运行时**：`riskguard bootstrap` 把最小运行文件集装进 `~/.riskguard/runtime/<version>/`，
  生成逐文件 sha256 的 `runtime-manifest.json`；**Agent 的 hooks/plugins 指向 runtime 而不是 git clone** ——
  移动或删除源码仓库后 RiskGuard 仍然工作（真机验证：hook 指向 runtime 路径，runtime hook 自检独立 PASS）。
- **统一 launcher** `bin/riskguard.mjs`（仓库内与制品内都有）—— 用户不再需要输入 `packages/cli/src/index.ts`。
- **发布制品**：`scripts/build-release.ts` 产出 `dist/agent-risk-guard-v<version>/`（runtime 文件集 + launcher +
  `runtime-manifest.json` + `SHA256SUMS.txt` + `tar.gz`）；CI 构建 → 跑平台无关测试 → `sha256sum -c` 校验。

### 验证

本地全量 **190 passed / 0 failed**；CI（Node 22/24，Ubuntu）green（6 项 Windows-only 真机测试按设计 skip）。

## English

### The problem this release solves

Three things, all leading to the same outcome — **you think you are protected, but the wire was cut long ago**:

1. **Hooks pointed at a git clone.** The installer pointed the agent's hook at the source repository path, so
   **moving, renaming or deleting that repository silently killed the protection** — while the status page could
   still look fine.
2. **The manifest was not in the transaction snapshot.** When an install or repair failed and rolled back, the
   config files were restored but the manifest was not, leaving a state where "the record does not match
   reality" — and the next repair would misjudge based on it.
3. **Every ACTIVE looked the same.** A runtime self-test that really spawned a dangerous payload (dynamic) and a
   check that only inspected wiring and hashes (static) were **presented identically**, so a user could not tell
   "verified" from "looks configured".

### What changed

- **The manifest is now part of the transaction snapshot**: an existing manifest is backed up exactly before
  install (restored and sha256-verified on rollback); if it did not exist, `existedBefore=false` (rollback
  removes what this run created).
- **Repair detection**: a manifest that exists but whose wiring is broken (BROKEN / INSTALLED) makes `install`
  run as a repair and report `repaired successfully`, instead of a misleading `already installed`; only
  "no changes + healthy ACTIVE" counts as already installed.
- **`verificationMode` is shown honestly**: `dynamic` (Claude Code / Codex — a real interception self-test),
  `static` (OpenCode / DSH — wiring + artifact + integrity), or `none`; both `status` and `doctor` display it,
  so the two are no longer conflated.
- **Portable runtime**: `riskguard bootstrap` installs the minimal runtime file set into
  `~/.riskguard/runtime/<version>/` with a per-file sha256 `runtime-manifest.json`, and **agent hooks/plugins
  point at the runtime instead of a git clone** — RiskGuard keeps working after the source repo is moved or
  deleted (verified on a real machine: the hook points at the runtime path and the runtime hook self-test passes
  independently).
- **A unified launcher** `bin/riskguard.mjs` (present both in the repo and in the artifact) — users no longer
  type `packages/cli/src/index.ts`.
- **Release artifacts**: `scripts/build-release.ts` produces `dist/agent-risk-guard-v<version>/` (runtime file
  set + launcher + `runtime-manifest.json` + `SHA256SUMS.txt` + `tar.gz`); CI builds it, runs the
  platform-independent tests, then verifies with `sha256sum -c`.

### Verification

**190 passed / 0 failed** locally; CI (Node 22/24, Ubuntu) green (the 6 Windows-only real-machine tests skip by
design).
