## 中文

### 这一版要解决什么问题

RiskGuard 会拦危险命令，但它说的话**只有自己听得懂**。一个已经在用 OWASP **Agent Control Standard (ACS)**
的平台，同时接了好几个护栏，无法消费 RiskGuard 的判定 —— 没有共同的线上格式，也没有共同的"这个 Agent
到底暴露了哪些面、失败时是 fail-open 还是 fail-closed、边界在哪一层"的描述。
结果是：能拦住，但**说不清楚能不能信**。

### 改变了什么

- **`packages/acs/` 独立边界协议包**：inbound（ToolCallRequest → RiskEvent）/ outbound（Decision → AcsResult）/
  Gateway（`evaluateAcsToolCall()`，validate → map → evaluate → map → validate）。
  原则：**ACS 是边界协议，不是核心模型** —— RiskEvent / Policy Engine 保持标准无关，Core 不依赖 ACS。
- **Capability Taxonomy（11 个）**：`filesystem.read/write/delete`、`shell.execute`、`git.modify/git.destructive`、
  `process.execute`、`network.connect`、`credentials.read/write`、`mcp.invoke`。
  **Capability ≠ Risk**：风险判定仍由规则族负责。
- **RiskGuard 扩展命名空间**：`extensions.riskguard { ruleId, degraded, verification, monotonic, acsVersion, profile }`
  —— **不往 ACS 官方 schema 顶层加字段**。
- **Compatibility Schema v2**：每 Agent 增加 surfaces（带 EvidenceState）、`enforcementDetail`、`sandbox`、
  `policy.policyScope`、`bypass`、**`hookFailureSemantics`**（fail-open / fail-closed / warning-and-continue / unknown）、
  `conditionalAvailability`（如 Windsurf Restricted Mode 下 hooks 不加载）、`securityBoundaries`（L0–L5）、
  per-capability 矩阵；**v2 未声明的字段一律 `unknown`，不伪造 `false`**；loader 兼容 v1→v2。
- **Conformance Framework C1–C10**：Hook Available / Pre-execution / Hard Deny / Deny survives bypass /
  Safe allowed / Dangerous blocked / Tool never executed / Hook failure semantics / User bypass / MCP coverage，
  状态 PASS / FAIL / SKIP / UNKNOWN。它与 D0–D4 是**两个维度**，不互相替代。
- **CLI `riskguard acs evaluate`**（stdin ToolCallRequest → stdout Result，fail-closed）；官方 shape 的 golden fixtures；
  **自动生成的 Agent Security Matrix**（`docs/generated/agent-security-matrix.md`，CI `--check` 防漂移）。

### 验证

**235/235 测试通过**，main CI green。
定位：**OWASP ACS v0.1 aligned（experimental）** —— 不宣称 compliant / certified（ACS 当时仍是 Public Preview）。

## English

### The problem this release solves

RiskGuard could block dangerous commands, but it spoke a language **only it understood**. A platform already
using the OWASP **Agent Control Standard (ACS)** alongside several other guardrails could not consume RiskGuard's
decisions — there was no shared wire format, and no shared way to say which surfaces an agent actually exposes,
whether its hook **fails open or closed**, and where the boundary layers sit. The result: it could block, but
**nobody could say whether to trust it**.

### What changed

- **A separate boundary-protocol package `packages/acs/`**: inbound (ToolCallRequest → RiskEvent), outbound
  (Decision → AcsResult), and a Gateway (`evaluateAcsToolCall()`: validate → map → evaluate → map → validate).
  Principle: **ACS is a boundary protocol, not the core model** — RiskEvent / the policy engine stay
  standard-agnostic and the core never depends on ACS.
- **Capability taxonomy (11)**: `filesystem.read/write/delete`, `shell.execute`, `git.modify/git.destructive`,
  `process.execute`, `network.connect`, `credentials.read/write`, `mcp.invoke`. **Capability ≠ Risk**: risk
  judgement still belongs to the rule families.
- **A RiskGuard extension namespace**: `extensions.riskguard { ruleId, degraded, verification, monotonic,
  acsVersion, profile }` — **no fields are ever added to the official ACS schema top level**.
- **Compatibility Schema v2**: per agent, surfaces (with EvidenceState), `enforcementDetail`, `sandbox`,
  `policy.policyScope`, `bypass`, **`hookFailureSemantics`** (fail-open / fail-closed / warning-and-continue /
  unknown), `conditionalAvailability` (e.g. hooks not loaded under Windsurf Restricted Mode), `securityBoundaries`
  (L0–L5) and a per-capability matrix; **fields not declared in v2 are reported as `unknown`, never faked as
  `false`**; the loader migrates v1 → v2.
- **Conformance Framework C1–C10**: Hook Available / Pre-execution / Hard Deny / Deny survives bypass /
  Safe allowed / Dangerous blocked / Tool never executed / Hook failure semantics / User bypass / MCP coverage,
  with PASS / FAIL / SKIP / UNKNOWN. It is a **different axis** from D0–D4, not a replacement.
- **CLI `riskguard acs evaluate`** (stdin ToolCallRequest → stdout Result, fail-closed); official-shape golden
  fixtures; and an **auto-generated Agent Security Matrix** (`docs/generated/agent-security-matrix.md`, guarded by
  a CI `--check`).

### Verification

**235/235 tests pass**, main CI green.
Positioning: **OWASP ACS v0.1 aligned (experimental)** — not compliant, not certified (ACS was still a Public
Preview at the time).
