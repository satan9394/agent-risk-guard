## 本轮目标

核心目标只有一句（任务书开头）：

> **RiskGuard 的 ACS 输入和输出必须能够通过 OWASP ACS v0.1.0 官方 JSON Schema 验证，
> 而不是只通过 RiskGuard 自己的简化校验。**

即补齐 v0.2.0 缺失的 **Wire Schema Conformance**（线协议 / JSON Schema 层兼容）：
官方 Schema > 本地推测类型；官方 Wire Format > 自定义方便格式；固定版本 > latest；小补丁 > 重写架构。

## 交付内容

### 1. 版本统一为完整 SemVer（§三）

| 符号 | 值 | 说明 |
|---|---|---|
| `ACS_SPEC_VERSION` | `0.1.0` | 官方 wire spec 版本（完整 SemVer，写进 acs_version） |
| `ACS_VERSION` | `0.1.0` | 兼容别名 = `ACS_SPEC_VERSION` |

禁止再把 `0.1` 写进 ACS wire payload（官方 acs_version 要求 `^\d+\.\d+\.\d+$`）。

### 2. ToolCallRequest 对齐官方 schema（§四/§五/§六）

- `packages/acs/src/types.ts` 重写为官方 JSON Schema 镜像：
  - required = **tool + arguments**；capability **可选**（官方工具调用允许无 capability）。
  - `tool`：name 必填，version/provider 可选；**移除 protocol**（非官方字段）。
  - `arguments`：value-wrapper 形状 `{ value, provenance? }`（`AcsArguments` / `AcsArgumentValue`）。
  - 非官方顶层字段（environment / provenance[] / requestId / tool.protocol）移出官方 payload 类型（§六）。
- `src/inbound.ts`：Layer 1 校验对齐官方 required（arguments 必填、capability 可选、fail-closed）。
- `src/arguments.ts`（新）：`unwrapAcsArguments()` 统一解析 value-wrapper（§三十三），
  容忍 v0.2.0 遗留裸值（官方 schema 仍会拒绝，判据始终在 Layer 2），
  保留参数级 provenance + `argumentPath=/arguments/<key>`（§三十四/§三十五）。

### 3. Capability 推导（§三十一/§三十二）

- `src/capability-map.ts` 新增 `deriveAcsCapability()`：raw_command 分类优先（classifyShellCommand），
  其次 tool.name + operation。例：tool.name=shell + raw_command=`git reset --hard` → **git.destructive**。
- 解析规则：capability **显式出现** → 官方名归一（未知 → fail-closed，绝不静默 reinterpret）；
  capability **缺失** → 推导；推导不确定 → fail-closed deny。
- `src/tool-call-request.ts`：capability 解析 + unwrap 后的 arguments 提取 target +
  参数级 provenance → `context.metadata.provenance`（含 argumentPath）+
  envelope metadata → `context.metadata.acs`（§三十六，Core 不解释 ACS）。

### 4. Request / Response Envelope（§七/§十/§十二）

- `src/envelope.ts`（新）：`AcsRequestEnvelope`（jsonrpc/method/id/params）、`AcsResponseEnvelope`
  （result XOR error）、`validateAcsRequestEnvelope()`（Layer 1）、`buildAcsResultEnvelope()`
  / `buildAcsErrorEnvelope()`、JSON-RPC 错误码常量（-32700/-32600/-32602，§四十一）。
- params 必填：acs_version / request_id / timestamp / metadata / payload；metadata 必填 agent_id / session_id（§十）。
- fixtures 全部使用合法 UUID（§十一：禁止 test-1 / abc / request123）。

### 5. Gateway 双模式（§八/§九/§三十七/§三十八/§三十九/§四十）

- **Mode A — Payload Only**：`evaluateAcsToolCall()`（默认 CLI 模式，fail-closed deny 保留）。
- **Mode B — Official Envelope**：`evaluateAcsEnvelope()`——Request Envelope → Response Envelope，
  是**唯一官方 conformance 对象**（§九）。`result.request_id` 回显 `params.request_id`（§三十七），
  `response.id` 回显 `request.id`（§三十八）。
- 错误语义严格分离（§四十）：invalid JSON → -32700（id null）；invalid envelope → -32600；
  params/payload 非法 → -32602；valid request 但安全映射失败 → **ACS deny + degraded=true**（非协议错误）。

### 6. Result / Modification / ask / defer 官方化（§十三~§二十三）

- `src/result.ts`：官方必填 `type="final"` / `acs_version="0.1.0"` / `request_id`（wire 回显 /
  payload 由 gateway 生成合法 UUID）；request_id 不再放 extensions（§十四）。
- **modify 用官方 modifications object**（§十七）：`parameter_overrides`（trash 改写，§十八/§十九），
  值保持 value-wrapper 形状（应用改写后仍能通过官方 tool-call-request.json）。
- **§二十 行为变更**：deny+safeAlternative 仅在 arguments 能明确表达 operation/path/mode 时才 modify；
  否则 deny，reasoning 带固定说明
  `Safe replacement is available conceptually but cannot be represented safely in this ACS payload.`
  （例：仅 path 参数的 filesystem-delete 从 modify 改为 deny，遗留 fixture `_expected` 同步更新）。
- **description-only 不是合法 modification**（§二十一）：Layer 1 与官方 modifications.json 双重拒绝。
- ask_details 官方化（approver/question/timeout_seconds，§二十二）；defer_details 官方化
  （reason/resolution_method/resolution_timeout_ms，§二十三）。
- `src/outbound.ts`：validateAcsResult 至少检查 type==final、acs_version SemVer、request_id UUID、
  decision 合法、官方决策条件约束（deny/modify/ask/defer 必带 reasoning 等，§十六）。

## 关键决策记录

- **capability 缺失 ≠ 拒绝**：官方 optional 不能人为变成 mandatory；推导不确定才 fail-closed（§三十二）。
- **显式未知 capability 不静默 reinterpret**：capability 显式给出但无法归一 → 直接 fail，
  不允许从 tool.name 猜测替代（否则 `magic.teleport` 会被当成 shell.execute 低估风险）。
- **modify 宁缺毋滥**：无法在官方 arguments 结构里安全表达 trash 改写 → deny + 固定说明（§二十），
  不输出空 parameter_overrides / description-only 的"假 modify"（§二十一）。
- **协议错误 ≠ policy deny**：wire 模式 invalid JSON-RPC 输出 JSON-RPC error，绝不伪造 deny result（§四十）；
  安全映射失败才输出 deny + degraded=true。
- **vendor schema 只读**：hash 完整性由 CI 锁死；更新 = 换 upstream commit + 重新同步 + 人工 review（§五十五）。
- **引用同一会话早前结论**：upstream pinned commit 的选择依据（f46d260 引入 v0.1.0 spec 且此后未变）
  在本会话中用 `git ls-remote` + `git diff` 实测确认。
